## 📍 Current State

The full community pipeline is now **database-first** and resumable at the
community level. `data/pipeline_state.json` is a read-only mirror; the database
is the source of truth.

### What was added
1. **New tables** (`modules/community/database.py`):
   - `community_pipeline_status` — per-community resume flag
     (`pending`/`processing`/`partial`/`completed`/`failed`), `sort_order`.
   - `community_condenser_runs` — one row per `(community, condenser)`.
   - `community_urls` — many-to-many link of inspected URLs to communities.
   - `schema_migrations` — marker to make migration a fast no-op after first run.
2. **Migration** (`modules/community/migration.py`, `migrate_database.py`):
   additive + idempotent; retains all data; backfills legacy
   `source_urls.community_slug` into `community_urls`; reconstructs legacy
   progress.
3. **DB-first pipeline** (`modules/community/full_pipeline.py`):
   register-all → process first incomplete → flag `processing` → run remaining
   condensers → `completed`/`partial`.
4. **URL attribution** threaded through `url_tracker.py`, `agent.py`,
   `web_condenser.py`, `browser_condenser.py`, and the browser runner.
5. **Viewer + PowerShell summary** now surface pipeline status, condenser runs,
   and URL↔community links.

## 🎯 How the new flow works

1. Every known community is registered in `communities` +
   `community_pipeline_status` before processing (stable `sort_order`).
2. A community is flagged `processing` while its condensers run; every URL
   inspected for it is linked in `community_urls`.
3. It is marked `completed` when all selected condensers finish (`done`, or
   `skipped` when inapplicable, e.g. Gemini unconfigured). Errors leave it
   `partial` for retry.
4. A restart begins at the first community whose status is not `completed`.
